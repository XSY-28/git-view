# 固定端点的版本比较

2026-10-06。第四批只增加读取与比较；暂存、提交及分支操作继续使用既有 operations/git-write 边界。

## 比较语义

先把 A/B 的 HEAD、完整引用或提交 ID 解析为本机的完整提交 OID。引用通过 check-ref-format 校验；提交 ID 使用对象前缀消歧，避免被同名十六进制分支遮蔽。输入不接受 revision 表达式、路径或任意 Git 参数。

| 输出 | 固定对象及含义 |
| --- | --- |
| A 独有提交 | A 可达且 B 不可达的提交 |
| B 独有提交 | B 可达且 A 不可达的提交 |
| A → B | 两个提交树的文件内容比较 |
| 共同祖先 → B | 唯一可确定 merge-base 的树与 B 的树比较 |

独有提交按拓扑分页，与内容差异分开查询。所有后续读取使用快照的 OID；移动分支不会改变既有分页的端点。主动刷新创建新的观测并重新解析符号端点。共同祖先查询使用 `merge-base --all`；多个结果全部显示，不任意挑选一个。浅仓库保守标记历史和计数不完整，仍可比较本机已有端点树，不开放共同祖先模式。无共同祖先也仍可比较两个端点树。

比较读取使用原始对象，禁用 refs/replace；存在替换引用时明确提示。legacy grafts 改写祖先关系时拒绝本功能。缺失提交/树使相应查询失败；文件预览前检查双方的 blob，缺失 blob 不使用工作文件补充，不自动联网。改名条目保留原始新旧路径，纯改名仅显示路径元信息。

语义依据：[Git diff](https://git-scm.com/docs/git-diff)、[merge-base](https://git-scm.com/docs/git-merge-base)、[rev-list](https://git-scm.com/docs/git-rev-list)。

## 状态与职责

- `contracts/comparison.ts` 定义受限端点、结果、方向及快照预算；传输只新增三个窄查询，不新增任意命令出口。
- `git-cli/comparison.ts` 解析端点、核对历史边界、读取共同祖先/独有提交/树差异；`diff.ts` 与既有查询共享路径寻址、blob 检查和文本预览限制。
- core 保存每会话最多 16 份比较，单份结果最多 1 MiB。分页游标另有既有上限，绑定比较 ID、工作区、方向和历史边界。新 generation、写入和会话关闭都会清理观测；文件身份由 core 从该观测的实际清单取得。
- `ComparisonView` 负责控件和展示；`useComparison` 独立管理比较、文件及两侧分页的请求。复用 RequestGate、ChangeList、DiffView、ReadFeedback、文件筛选和键盘导航，不把 Git 语义写进组件。
- UI 按 worktree 记住端点，返回该视图时重新读取；不缓存旧会话的结果。刷新/切端点/切基准/筛选排除所选文件都会使相关旧成功、错误及分页失效。取消独立读取后，焦点刷新不会擅自恢复它，显式重读或新仓库失效事件可恢复。

结果超限或不完整不会伪装成空列表。树差异结果不承诺永久保存对象；对象在后续读取前被清理时，返回明确的缺失错误。本批不实现任务基线、文件历史、blame、搜索、stash/reflog、fetch 或历史重写。
