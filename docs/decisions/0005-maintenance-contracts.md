# 重复文件、测试定位与读取状态

## 重复文件

源码目录中的编号副本会进入 TypeScript 的 include 范围。清理前应比较原件和副本，把副本及差异归档到项目之外，再移出源码目录；内容不同不代表应该覆盖原件。

`pnpm check:duplicates` 检查项目根目录及 apps/packages/tests/scripts/docs，遇到与现有原件对应的 `文件 2.ext`、`文件 12.ext` 等编号副本时失败。检查不读取内容，不删除文件，也不跟随符号链接或扫描生成目录。没有对应原件的独立编号文件不作为副本处理。该检查接入 typecheck，因此本地检查和现有 CI 都会运行。它防止相同命名方式的副本再次混入，不检测所有可能的重复内容。

## 测试定位与语言

仓库标题通过 heading 角色定位；提交行、历史滚动区、差异滚动区、引用、最近仓库和调查容器使用独立于样式类名的测试 ID。需要进一步限定范围时可以组合属性选择器，但不再依赖上述样式类名。其他定位器按实际维护问题渐进迁移。

语言测试对应用自有控件检查具体英文名称和选项；仓库内容使用真实中文样本，验证切换英文后仍保持原文。页面或工具容器的全部文本不应通过“不能含中文”检查，因为文件、代码、提交说明和引用属于用户内容。漏翻译仍应通过应用文案断言发现。

## Resource 与状态所有权

三个读取模块共用 state/resource.ts 中的 Resource 类型。本次只统一定义，不改变运行时转换。

| 情形 | value / stamp | 读取反馈 |
|---|---|---|
| 尚未读取 | 无 | 空闲 |
| 首次读取或选择新对象 | 无 | 加载；耗时较长时提供取消 |
| 对原对象刷新 | 保留旧结果及旧 stamp | 加载、过期；旧内容继续可读 |
| 读取成功 | 替换为新结果及新 stamp | 空闲 |
| 读取失败 | 如有旧结果则保留 | 错误；提供重试 |
| 取消读取 | 如有旧结果则保留 | 中性取消提示；提供重新读取 |
| 外部失效或仓库操作使结果过期 | 如有旧结果则保留 | 过期；不能据此执行需要新观测的动作 |
| 对象、范围或仓库切换 | 按对应选择策略清空 | 新上下文重新读取 |

“当前请求阶段”和“是否有上次结果”不是互斥状态，因此不采用只有 idle/loading/ready/error、仅 ready 有值的联合。旧 stamp 标识旧结果，不能在刷新开始时伪装成新观测。所有迟到成功、失败和完成事件继续由 RequestGate 检查。

App 仍负责当前仓库、选择、刷新代次和跨视图导航；版本比较及历史调查已经各自拥有读取 hook。本次没有发现必须改变这组所有权才能解决的问题，因此不机械拆分 App。若后续状态转换出现重复缺陷，或新增功能迫使多个模块修改同一组转换，再以完整转换表设计联合/状态机，并在保持单一状态所有者的前提下抽取 hook。

验收涵盖刷新时的滚动及展开状态、失败和取消后的旧内容、过期结果拒绝、语言切换，以及本地与 CI 的副本检查。类型检查通过不能代替这些行为验收。
