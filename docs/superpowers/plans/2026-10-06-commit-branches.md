# 第二、三批：普通提交和本地分支

用户已授权完成两批后上传。仅提交本批相关变化；此前未提交的安装脚本及其说明保持原样。上传默认推送当前功能分支到现有 origin，不强制推送、不合并主分支。

## 完成标准

- [x] 普通提交只使用已暂存内容，支持首次提交，禁止空说明、amend、自动暂存与推送。
- [x] 保留正常 hooks/签名，在确认页明确授权；展示实际 OID、parent/tree、预览差异与剩余修改，失败不伪造成功或盲重试。
- [x] 分支从预览时固定的 HEAD OID 创建且不切换；已有分支不覆盖；独立切换仅允许本地现有分支及干净工作区。
- [x] 拒绝冲突、进行中的操作、过期前提、占用 worktree，以及目标版本激活的外部过滤器；不自动 stash、不强制丢弃、不覆盖忽略文件。
- [x] 复用独立协议、协调器和持久回执，补充 commonGitDir 串行与失效；真实故障恢复不重复提交。
- [x] 真实临时仓库测试、浏览器回归、桌面构建与原生窗口验证通过，保留平台限制。
交付动作：精确提交并推送，远端提交号在最终交付回执核对。

## 实现选择

使用正常 `git commit` 和 `git switch`，由 Git 执行 hooks/签名及自身锁检查；不自行重造提交钩子流程。分支创建使用带旧值为零的 `update-ref`，保证不覆盖已有引用。预览只读；执行前再次核对 HEAD/index/配置和目标引用。外部 Git 与编辑器不受应用锁约束，执行后读取实际事实，不能承诺跨外部进程的事务。

写入前持久化意图；提交用唯一 reflog 标记及 parent 关系核实来源，记录真实新 tree 与预览内容是否一致。中断或输出丢失时只查证据，不重发命令。hooks 可修改文件、暂存区或其他引用，界面明确授权且保留诊断。
