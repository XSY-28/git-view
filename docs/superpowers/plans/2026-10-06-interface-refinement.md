# Git View：三轮界面优化计划

日期：2026-10-06。三轮均已实现并完成本轮验收。运行证据见 [第一轮验收](../../verification/2026-10-06-interface-round1.md)、[第二轮验收](../../verification/2026-10-06-interface-round2.md)、[第三轮验收](../../verification/2026-10-06-interface-round3.md)。

本计划整理已经实现的只读查看器。这里的第一、二、三轮是界面交付批次，独立于 [产品第二、第三阶段](2026-10-06-next-stages.md) 的 2A、2B 和 V0.3；不新增任务基线、历史调查或 Git 写操作。

## 目标与约束

减少重复入口，明确操作结果，并让文件和差异占据更多空间。常用动作保留可发现的入口，较少使用的完整元数据按需展开，不以隐藏必要状态换取简洁。

- 当前分支、所选历史范围、当前仓库/worktree 是不同对象，展示和操作各有明确含义。
- 仓库切换仍复用原有控制器；引用筛选只改变查询，不 checkout。UI 不增加 Git 命令或第二套业务状态。
- 比较语义、读取失败、过期和不完整提示继续可核对；请求身份检查、刷新期间选择和滚动保持继续有效。
- 窄窗口可操作，关键入口可通过键盘访问；各轮使用真实临时仓库及界面流程验证，截图不代替操作结果。

## 第一轮：整理布局和入口

- [x] 顶部仓库名称作为统一切换入口，收纳打开仓库、最近仓库、多个 worktree、完整路径和复制、手动路径。保留原生文件夹窗口与 `⌘/Ctrl+O`，取消和失败继续保留当前仓库。
- [x] 侧栏聚焦历史范围，移除重复的最近仓库/worktree 切换；引用筛选与当前分支标记分开，范围重置集中到侧栏。
- [x] HEAD 已在加载列表时显示“定位 HEAD”；否则显示“查看 HEAD 历史”，使范围变化能在点击前预期。
- [x] 压缩品牌、仓库标题和状态区域，保留紧凑工具栏及一个只读标记；完整路径移入切换器。
- [x] 提交摘要默认展示标题、作者、日期、短 ID 和比较语义。完整 ID、父提交、精确时间和完整基准按需展开；复制 ID 有独立入口。
- [x] 变化文件列表默认展开，可收起；长列表独立滚动，减少详情对差异区域的占用。

实现拆分为仓库切换器、历史范围展示和提交摘要组件，共享的历史范围名称有单一来源；异步读取与仓库身份仍由现有 App/控制器管理。

可检查的完成标准：同一入口能打开和切换仓库/worktree，历史筛选不改变实际 HEAD，首次提交及 merge 的比较语义默认可见，完整路径/ID 可查看与复制，桌面和窄窗口均无水平溢出；同提交刷新不会重置展开状态或引起操作目标位移。当前自动验证为类型检查、89 项单元/集成测试、21 项浏览器测试及 Web/桌面构建通过；原生窗口核对范围与证据以本轮验收记录为准。

## 第二轮：优化差异查看和文件导航

- [x] 精简重复的原始补丁元信息，保留行号、变化区段、重命名和模式变化；原始补丁可按需查看或复制。
- [x] 纯文本预览只显示适用控件；调整差异模式命名和两侧对象标签，使实际比较关系直接可见。
- [x] 统一文件与提交列表的方向键、焦点和滚动行为，并增加文件筛选。

验收重点：已暂存/未暂存两份比较、未跟踪预览、首次提交和第一父比较的内容语义不变；单列与并排行号及对齐正确；键盘找文件、切换文件及筛选后的选中状态一致。

本轮交互约定：差异模式对外使用“单列／并排”，内部保存值沿用现有协议；未跟踪文本仅使用单列预览和折行。默认隐藏重复补丁头，模式、路径变化与未换行标记仍可核对；原始补丁按需展开，截断时明确是已获取部分。文件筛选匹配新旧路径，当前改动和提交文件分别记忆筛选词；当前项不匹配时取消相应读取并清空详情，清除筛选不会自动抢选。上下方向键及 Home/End 只导航可见、可读取的条目，键盘移动保留列表焦点。

实现与验证：`ChangeList` 复用文件筛选和导航；提交图共用方向键目标计算；`diff-presentation` 统一比较对象和补丁呈现。Git 读取接口与事实核心保持原有职责。最终类型检查、107 项单元/集成测试、28 项浏览器测试、Web/桌面构建通过；原生窗口验证了补丁展开/复制、文本预览、筛选清选、上下键与跳过折叠组、首次提交空树比较。

## 第三轮：统一刷新反馈并完整验收

- [x] 保持刷新动作的含义稳定，短暂后台读取采用轻量反馈，耗时操作再显示范围明确的取消入口。
- [x] 统一自动/手动刷新、取消、错误与过期提示，减少内部读取任务对用户操作的干扰。
- [x] 完整走查切仓库、切文件、查历史、外部修改、失败恢复和窄窗口流程，并重新打包桌面版。

验收重点：不同请求的旧成功和旧错误都不能覆盖当前选择；后台更新不打断正在进行的交互；取消和失败保留正确的旧结果及状态；构建、测试与原生操作证据分别记录。真实使用者能否在无说明情况下完成主要任务仍需试用验证，不能从自动测试数量推断。

本轮实现：共享反馈策略与时长、父子取消协调、身份不匹配响应终结、保留同一提交的重试；固定刷新入口，短读取轻量显示、慢读取具名取消，取消后抑制排队/聚焦刷新，错误可恢复且完整信息可通过键盘读取。并排不折行长文本按内容计算列宽，避免跨列重叠。

最终类型检查、122 项单元/集成测试、41 项浏览器测试及 Web/桌面构建通过。原生窗口核对系统文件夹选择/取消、切换仓库、手动与外部刷新、选择及展开保持和首次提交比较；延迟/故障/竞态与窄窗口的证据边界见第三轮验收记录。
