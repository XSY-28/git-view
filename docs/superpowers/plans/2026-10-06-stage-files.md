## 实施落点

1. contracts 的基础模型、读请求与写请求分开；现有导出兼容。
2. git-write 只负责受限索引写入与结果证据。预览不改变仓库；执行使用冻结内容、独立临时索引和 Git 的 index.lock，最终原子安装。首批对无法可靠复现的内容转换明确拒绝，不执行外部程序。
3. operations 负责预览、有效期、队列、持久回执与恢复。HTTP 仅已授权页面有写入口；桌面使用独立 write 信封；读请求不扩权。
4. 页面复用现有文件列表与差异视图，按勾选文件预览、执行和核实；写入期间暂停刷新，结束后失效旧读取。
5. 真实临时仓库和故障注入验证，桌面打包及原生核对，最后一次本地提交。
