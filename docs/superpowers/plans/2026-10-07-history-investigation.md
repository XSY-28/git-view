# 第五批：历史调查

承接已确认的批次安排：提交搜索、文件历史、行来源、stash 和 reflog 查看。操作前后基线属于第六批。

## 完成标准

- [x] 按标题、作者、完整/短提交 ID、精确文件路径搜索；历史范围和固定 tips 明确，分页不混入移动后的分支。
- [x] 从文件差异进入文件历史，也可指定 HEAD/引用/提交及仓库内路径；第一父链跟踪普通重命名，明确合并、浅历史和读取上限。
- [x] 查看比较前、后的完整文件行来源，绑定真实提交和当时路径；不读取未提交工作文件，不给新增工作行伪造作者。
- [x] stash 默认比较第一父基准 → 工作区快照；暂存区与未跟踪快照独立选择，不 apply/pop/drop。
- [x] reflog 保留本机记录的 old/new OID、操作者、时间、消息，可查看提交及比较前后；缺失/过期/不可用对象明确展示。
- [x] 查询契约、只读适配器、会话观测与 UI 分开；限额集中配置，沿用请求门禁、错误/取消反馈、中英切换及窄窗口布局。
- [x] 真实仓库、只读指纹、分支移动、重命名/合并/浅历史、缺失对象、旧成功/错误/分页、worktree 隔离通过；完整回归与固定安装版原生窗口验证。

## 架构

`contracts/investigation.ts` 定义输入和结果。不可变对象读取共用只读 runner 与对象/历史边界检查。调查 reader 保存有字节和数量上限的观测，cursor、文件及记录详情绑定 worktree 与观测 ID。core 只授权当前会话实际返回的文件/记录，刷新和写入清除授权。界面按搜索、文件、stash/reflog 拆组件，共用身份门控和差异组件。

文件历史首版采用第一父链范围，不承诺所有合并路径及复制追踪。reflog 首版读取 files ref storage 的本地日志；其他存储格式明确拒绝，不能冒充没有记录。所有新增查看入口均不联网、不修改用户仓库。

完成证据见[第五批验证](../../verification/2026-10-07-history-investigation.md)；Spotlight 搜索界面保持未验证，其他平台原生窗口不由本机结果推断。
