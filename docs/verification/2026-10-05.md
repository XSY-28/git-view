# 2026-10-05 · 第一轮施工与验收

本次交付可运行的只读工具、生产构建与 Codex skill 安装包。**这是已有实测证据的施工版本，尚不声称完整工程 MVP 验收结束。** 未测项目列在本文末尾；原始产品边界继续以 `MVP-KICKOFF.md` 为准。

## 实现范围

| 功能 | 本次实现 |
| --- | --- |
| F01 | 绝对路径/子目录解析，canonical worktree 身份，最近仓库去重与本机持久化，路径错误 |
| F02 | 分支、HEAD、unborn、detached、冲突和操作标记 |
| F03 | HEAD→index、index→worktree、未跟踪预览；新增/删除/修改/重命名；特殊路径及明确降级 |
| F04 | 本机已有引用的提交图，固定 tips 的 200 条分页，首次/第一父比较，浅克隆边界，HEAD 定位和虚拟列表 |
| F05 | 三个确定性问题，观测身份、适用条件与可点击证据；冲突/不完整/操作中停止预测 |
| F06 | 刷新、焦点恢复、取消、保留有效选择、丢弃旧成功/失败；仓库变化检测与有界恢复 |
| F07 | 构建 CLI 的 open/inspect、循环复用本地进程、独立 skill 安装副本、宿主真实调用；全局安装后自动发现仍待验 |

依赖方向：schema→推导类型；纯规则/图布局不导入 UI 或 HTTP；core 通过 `GitAdapter` 注入读取器；本地 HTTP 组装；CLI 与浏览器消费同一接口。根依赖清单及 lockfile 固定实际构建版本。没有实现暂存、提交、fetch、stash、任务基线、云服务或 DSH。

## 性能

完整原始样本见 [performance.json](performance.json)。夹具为 10,000 提交、5,000 跟踪文件、200 个变化文件、首批 200 历史节点；刷新与 diff 各 20 次，包含本地查询与浏览器绘制等待。

测试机：Apple M5 Pro / 48 GiB。最终观测结果如下；应用启动只测一次，不称 p95。

| 指标 | 实测 | 约定目标 |
| --- | ---: | ---: |
| 应用进程冷启动至列表可见 | 624 ms | ≤ 3,000 ms |
| 刷新 20 次的 p95 | 315 ms | ≤ 1,000 ms |
| 文件 diff 20 次的 p95 | 350 ms | ≤ 1,000 ms |

“应用冷启动”指 Chrome 已启动、应用进程未运行。文件系统缓存为热：夹具刚生成，没有清空 OS 文件缓存。运行中无应用 diff 缓存；20 次选取固定的不同文件，刷新有意避开 700 ms 的去抖间隔。文件系统冷缓存及浏览器自身冷启动未测，不能由热缓存结果推断。

## 施工中发现并修复的问题

- 全局配置有 LFS 时不能一律跳过普通仓库。先安全检查实际文件在工作区及 index 中的过滤器属性，只有涉及外部过滤器才降级。
- Git 有时能以工作文件代替缺失 blob 来生成 diff。详情现在先检查所引用的 blob 对象确实存在，缺失对象不会被“正常 diff”掩盖。
- diff hunk 中的 `+++counter` / `---counter` 是 C++ 内容变化，不一定是文件头。解析器按 hunk 状态区别，新增回归测试。
- 无界 flex 高度会使虚拟历史渲染全部 200 行。滚动视口改为有界高度，浏览器断言 DOM 行数少于 40 并验证跨窗口键盘焦点。
- 新页面交换票据须保留同实例已有浏览器会话；失败或过期结果不能同时显示“没有提交/仓库干净”的空状态。
