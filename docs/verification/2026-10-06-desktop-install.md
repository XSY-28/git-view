# macOS 单路径安装与恢复验证

日期：2026-10-06。

`pnpm install:desktop` 将已构建的应用安装到固定的 `~/Applications/Git View.app`。更新前校验应用身份、版本、构建清单与资源哈希；旧安装保存为 ZIP，替换成功后注销并移除本次构建副本和旧安装的临时注册记录，再清理失效的 Git View 注册记录并刷新搜索服务。运行中的 Git View 会阻止安装，不会被强行退出。`--dry-run` 仅检查，不写入、注册应用或重启搜索。

后续本机迭代使用 `pnpm update:desktop`，先检查 Git View 已退出且没有安装锁，再顺序执行核心构建、桌面打包和上述安装；任一步失败均停止后续步骤。检查运行状态前不会生成新的构建副本。先退出运行中的 Git View，不手动复制或从构建目录启动应用。项目 `AGENTS.md` 同时要求后续 GUI 验收使用固定安装路径，避免另造同名测试 `.app`。CI 或仅打包仍使用 `pnpm build:desktop`。

已有安装重复显示时，可以运行 `pnpm repair:desktop-search --dry-run` 检查，再运行 `pnpm repair:desktop-search`。该命令不需要构建副本，不替换已安装应用；只注销文件已不存在的同 bundle ID 记录。发现其他仍存在的 Git View 应用时，会报告路径并停止，保留文件与注册状态。

搜索刷新使用当前用户会话中加载的 `com.apple.campo` 或旧版 `com.apple.Spotlight`。如果系统保护拒绝 `launchctl kickstart -k`，脚本核对原进程的所属用户和完整可执行文件路径后才发送 TERM；无响应时重新核对后发送 KILL。随后正常启动同一服务，检查新 PID 持续处于 running。失败时再次尝试启动服务并明确报错，不把安装成功误报为搜索已修复。安装后的搜索修复失败会保留已校验的最新版，可单独重试修复命令。

- dry-run 不修改文件或注册状态。
- 首次安装、更新与旧版 ZIP 保存。
- 运行中拒绝、资源损坏拒绝。
- 备份失败保持旧安装，注册失败回滚。
- 注销失败保留构建并报告恢复路径。
- 并发生成或修改构建时保留该副本。
- 更新清理完成后刷新搜索服务。
- 连续两轮迭代只保留最新安装，前两版 ZIP 可正确恢复，每次都刷新搜索。
- 尚未生成构建副本时检查能否更新；运行中的应用会在构建前被拒绝。
- 无构建副本的单独修复、失效记录清理与其他应用保留。
- 搜索重启失败及立即正常退出时重新启动服务。
- 系统保护拒绝强制重启时的处理、TERM 无响应时的恢复，以及所属用户或进程路径不匹配时拒绝发送信号。

测试使用系统 `plutil`、`ditto`、`unzip`；应用注册、进程查询与搜索服务操作使用替身。它们验证文件事务与恢复路径，不等同于真实系统端到端验收。当前 GitHub CI 在 macOS Apple silicon runner 上运行这组测试；其他平台跳过。

本机另执行了真实 `pnpm repair:desktop-search`：系统保护拒绝 `-k` 后，核实并结束原搜索进程，正常启动 `com.apple.campo`，新进程运行；前后正式安装的完整指纹相同。真实 `--check-ready` 在构建副本已清理的状态下返回 ready，后续注册表仍只有正式安装。这些结果只验证文件、注册和进程状态，实际搜索结果仍需按下述手动方法复测。尚未对其他 macOS 版本执行真实服务刷新，也未用统一更新命令重新构建或替换正式应用；下一轮真实更新是否持续只显示一个入口仍待验收。

## 手动验收方法

构建后退出 Git View，先执行 `pnpm install:desktop --dry-run`，再执行 `pnpm install:desktop`。核对固定安装路径、备份 ZIP、构建副本清理及应用启动；重新输入 Spotlight 搜索词，确认只显示一个 Git View。系统文件索引或应用注册表的计数不能代替搜索界面的实际结果。

命令输出的 `gui: "unverified"` 表示脚本只核实注册状态及搜索进程，仍需检查实际界面。它不会清空系统搜索索引或全局应用数据库；系统内部如何产生同一安装的重复结果仍未定位，搜索服务刷新属于本项目更新流程的处理措施。
