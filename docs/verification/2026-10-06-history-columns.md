# 宽图分列修正验收（2026-10-06）

## 根因与修正

用户复测发现：复杂历史横向滚动后，文字左右两侧都出现图线。上一版用 sticky 文字覆盖整行 SVG，只保证文字可见，没有把关系图限制在单独区域；原测试也遗漏了这一点。

本次把每行分成独立的关系图列和提交说明列：

- 图列有明确分界和 overflow 裁切，所有轨道仍保留在图内。
- 文字使用正常布局，不覆盖 SVG。作者过长时省略，提交 ID 与日期保持可读。
- 底部横向滚动条统一平移图列；文字位置不变。纵向虚拟列表继续负责两列的行对齐。
- 键盘选择和定位 HEAD 会把相应节点带入图列可视范围。
- 额外验出并修复窄窗口定位问题：定位 HEAD 保持提交列表可见，避免切入详情后在隐藏列表中消耗定位请求。

本次没有添加历史折叠或主线筛选，没有改变 Git 查询或真实父子关系。

## 历史简化的后续建议（未实现）

| 方向 | 适用场景 | 需要明确的边界 |
| --- | --- | --- |
| 紧凑布局 | 减少空白、行高和不必要的绕线 | 不隐藏提交，无法消除真实的并行复杂度 |
| 连续提交折叠 | 缩短无分叉区段，用“连续 N 次提交”按需展开 | 保留合并、分叉、引用和选中节点；分页外未知关系不能当作不存在 |
| 主线概览 | 观察一个分支的演进，先看合并结果，再按需看侧线细节 | 明确属于简化视图，可切回完整历史；多个引用一起作为起点仍可能很宽 |

对本次大量并行合并的场景，主线概览最能降低宽度。Git 的 `--first-parent` 沿合并的第一父提交遍历，省略通过其他父提交引入的逐次提交；它不自动识别名字为 main/master 的分支。见 [官方说明](https://git-scm.com/docs/git-log#Documentation/git-log.txt---first-parent)。实现时需区分主动收起的关系和分页尚未加载的关系，不能只加一个查询参数就声称完成。
