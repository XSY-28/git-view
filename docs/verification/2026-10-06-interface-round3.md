# 界面优化第三轮：刷新、取消与读取反馈

日期：2026-10-06。对应 [三轮界面优化计划](../superpowers/plans/2026-10-06-interface-refinement.md) 的第三轮。产品阶段仍为只读 2A，未引入 2B 或 Git 写操作。

## 变更与架构

- 顶部刷新始终表示重新读取仓库，不再变成取消按钮。仓库状态、引用、历史、提交详情及文件差异共用 `ReadFeedback`。
- 已有内容的短暂读取保留原内容，仅以轻量指示器表达更新；首次读取立即显示进度。超过 800ms 才提供范围明确的取消，时长集中于 `FEEDBACK_TIMING`。
- 取消采用中性状态，保留旧结果并提供重新读取；错误保留详情与重试。紧凑消息可用鼠标悬停或键盘聚焦阅读全文，展开区域内部可滚动，不改变外部行高和按钮位置。
- `ReadCancellation` 集中管理概览→工作区差异、提交详情→提交差异的依赖。取消同时清除排队刷新，窗口聚焦不会马上重启已取消读取；手动刷新和真实仓库变化可恢复读取。取消子读取不会因尚未返回的父结果而失效。
- 同一提交的刷新/重试复用保留内容的读取流程，不重新选择第一项；保留文件选择、元数据和文件列表展开状态、代码 DOM、横纵滚动与页面位置。
- 当前请求返回错误身份时终结为协议错误；旧请求的成功、错误和 finally 均不能改写新状态。可自动恢复的 STALE_RESULT 持续显示读取，不短暂发布错误警报或留下过程横条。
- 复制等短通知独立浮现后消失，不占据内容布局。无选中文件时，不再由父读取合成虚假的文件差异任务。
- 长行截图检查发现原有并排不折行文本会跨列重叠。表格改按内容确定宽度，完整文字仍可水平滚动查看；折行模式保持原行为。

反馈策略、时长和取消依赖有各自单一来源。App 继续协调会话、查询和选择；Git 核心、契约、传输与宿主没有加入第二套业务逻辑。

最终构建复制到 `/private/tmp/git-view-round3-gui/Git View.app`，以独立 `GIT_VIEW_HOME` 打开中文/空格路径的真实演示仓库。已从最终可执行文件确认嵌入上述 JS/CSS 资源。实际原生操作确认：

- 顶部始终显示“刷新仓库”；选择未暂存文件、展开原始补丁后刷新，仍保留选择和展开内容，更新结束后无残留读取提示。

- 从最近仓库切回原仓库，恢复原先未暂存文件的选择。
- 查看首次提交，显示空树→所选提交和 V1 内容；展开完整提交信息、收起变化文件列表后刷新，两种展开状态均保持。
