# 文件监听误触发连续刷新

日期：2026-10-07；macOS Apple silicon。

## 原因与修复

用户录屏中，读取时间持续改变，提交列表反复显示过期状态。本机监听探针在未主动编辑项目文件的 24 秒内收到 104 个事件，包含 Git 对象的元数据变化、忽略目录 `test-results` 的变化和根目录通知。原监听器把每个事件直接计入失效版本，前端据此不断推进读取代次，重新读取概览、引用、历史和差异。

监听事件现在只请求核对。核对 Git 可见的已跟踪和未跟踪路径、可变 Git 元数据及操作状态；状态确实改变时才增加失效版本。Git 对象缓存维护、被忽略的输出和父目录时间变化不会单独刷新界面。

- 根据仓库自身的忽略规则枚举文件，仍观察忽略目录中的已跟踪文件。
- 忽略规则和属性文件即使自身被忽略，也纳入核对；不执行 clean/process 过滤器。
- 工作文件包含大小、权限、mtime、ctime 和文件身份，保留同路径、同大小且还原 mtime 的编辑检测。
- 引用、reflog、stash、index、配置和操作状态继续更新；linked worktree 的共享 Git 目录继续监听。子模块观察其 Git 状态，避免把忽略输出的目录时间当成 HEAD 变化。
- 只在收到事件时核对；同一 worktree 的并发核对共享扫描。扫描期间的新事件留给下一次核对，首次扫描期间的失效不会被静默吸收。退出或移除监听器时取消扫描并关闭监听句柄。
- 核对失败仍报告监听不可用，保留手动刷新与返回窗口时的核对路径。
